# 面板功能与运营说明

本轮实现保留现有监控、AI主判定与规则兜底、匿名24小时帖子窗口、管理员鉴权及原有通知渠道。2026-10-26 用户已授权本地Git提交；不推送远端、不部署。

## 当前主面板

按2026-10-26用户评审，默认面板仅保留重置日历、单处下次重置预测、公告命中热力图和帖子。日期明细及帖子筛选按需展开。个人额度、监控管理、事件复核、预测账本、访客订阅等扩展模块不再占用首页；已有浏览器个人记录不被清除。下文扩展功能说明对应保留的实现，不表示它们仍在默认面板展示。邮件确认和退订管理通过通知链接进入独立视图，可返回日历。

当前采用Liquid Glass布局：桌面预测置顶、日历与热力图并排、帖子在下方独占整行；手机按预测、日历、热力、帖子排列。帖子随整页滚动，正文与译文限制行长，筛选和历史分页保留。根据后续评审已取消照片底图，使用纯色与CSS环境色，按钮选中态采用中性色。预测依据使用原位“查看分析依据 / 收起分析依据”按钮，长内容单独滚动，开关不随内容滚走。主题/语言切换后账户菜单自动关闭。

热力图卡片命名为“重置活跃度”，英文为Reset activity，按UTC日期展示重置相关消息条数，不代表独立完成的重置次数。首次加载默认选中UTC今天，展开当天消息并将窄屏图表定位到最近一周；无消息时保留今天格及明确空态。“今天”按钮可从历史日期或向前滚动的位置直接返回；明细始终保留，重复点击选中日期也不收起；自动刷新不覆盖手动选日。默认跟随今天的选择会随UTC日期更新，不主动抢焦点。

预测卡片先显示下一次重置的有效信息：明确预告展示时间窗口，历史估算标明“历史推算”，缺少时间的预告仍直接展示来源原文与发布时间。有效时间窗口以“预计”开头展示；日期或时区不明确时，主标题显示“下次重置时间待定”。例如“today is a reset”只在下方说明“提到帖文发布当天重置，具体时间与时区尚未明确”，不将原帖的“今天”解释成浏览者时区的当天。超过一天的无时间消息说明尚无后续完成确认并继续跟踪；已过期的明确窗口不作为新的预测或自动顺延。查看原帖与详细分析依据分开，“上次重置”在桌面预测右侧、手机预测下方展示完整日期和时间、距今时长及当前显示时区，采用来源确认完成的消息时间，不代表个人额度实际到账时刻。无记录、加载中和加载失败分别显示对应状态。

预测读模型新增可选pending_preview，记录最新待完成额度预告的来源、发布时间及same_day/unspecified提示，不更改既有status和时间字段语义。最新无时间预告会取代旧的明确时间窗口；发卡、未来时间戳的帖子及已被完成消息覆盖的预告不作为下一次额度重置。读取接口不请求AI，也不为了显示一个时间而制造预测窗口。

时区、帖子筛选及保留扩展页面中的下拉选择器统一使用站内玻璃菜单：选中勾选、深浅主题、选择后关闭、点击外部/Esc/Tab关闭；支持方向键、Home/End与字母检索。菜单按可用空间上下避让并限制在视口内，不再显示浏览器默认的选项弹层。原生select只保留为内部表单值与change事件适配，外部调用仍沿用原接口。

账户中的外观和语言使用单层纵向列表，每个选项独占一行：打开头像菜单即可选择，共两次操作，不再进入子菜单或返回上一级。桌面与手机交互一致，保留浅色、深色、跟随系统以及中文、English、自动语言；当前选项显示勾选，选择后立即应用并关闭整个账户菜单。选项点击区域至少44px高，键盘上下键跨选项移动，Home/End到菜单首尾，Esc直接关闭并归还头像焦点，Tab关闭菜单并继续页面导航；偏好刷新后保留。桌面导航栏的单击深浅切换继续保留。

界面统一使用“重置动态”统称，历史事件称“重置记录”，推送称“重置提醒”。帖子筛选为“全部 / 重置相关”，事件类型为“额度重置 / 重置卡发放”，状态为“已预告 / 跟踪中 / 已确认”。状态是系统自动识别的结果，不要求访客人工确认；“已确认”表示原帖明确确认完成，不是个人额度到账验证。预告时间已过也不会自动变成完成。

页脚包含项目介绍、独立站与标识归属说明、实际监控账号的X入口、个人Codex用量页、真实GitHub源码及Issues反馈入口、预测与数据覆盖边界、可展开的自动状态说明、版权及刷新频率。数据源检查间隔读取实际配置，和页面可见时60秒自动更新分开展示。

对于“today is a reset / reset day today”这类当天承诺，读取旧AI分析和新AI结果时均保守归为预告，不重写原帖、原始缓存或人工复核结论。唯一的同账号同类型当天承诺在24小时内遇到明确完成帖时，会自动关联并更新原事件；有多个可能关联的预告、跨账号或承诺过旧时保留独立完成记录，不阻止完成状态展示，也不要求人工才能继续。原有明确引用与明确时间窗口的关联规则继续保留。

## 阅读与个人记录

- 首屏显示保守预测，桌面同时显示最近完成公告；保留导航的检查入口。公告时间不代表个人账号到账时间。
- 月历使用七列日期与公告圆点，点击日期打开独立详情：桌面居中浮层，手机底部面板；内容独立滚动，不撑高日历。关闭按钮、点击外部或Esc均可退出，关闭后返回所选日期与原阅读位置。“今天”只返回当前日期，不自动打开详情。页面顶部可切换本地/UTC，月历、预测与帖子共用显示时区。长期热力仍明确标注UTC统计日；窄屏可横向浏览，缩窄窗口时保持最新日期可见，手动向前浏览后保留浏览位置。
- 事件时间线在服务端按账号、类型与阶段筛选后分页。明确引文或唯一时间窗关联预告与确认；额度完成公告按同账号六小时去重，发卡不混算。归组有歧义时保留独立记录供人工复核。
- 个人记录只保存在当前浏览器：5小时/周已用比例、精确重置时间、最早重置卡过期时间。状态文本只提取白名单字段，不上传、不保存原文，不读取账号凭证或本机文件。
- 本地解析支持`primary_window/secondary_window`中的`used_percent`及秒级`reset_at`，或有明确5h/weekly和已用/剩余百分比的文本。日期仅接受带`Z`或明确偏移的ISO时间；只有钟点或未知时区时不猜测。
- 页面打开时更新个人到期提示。关闭页面后的提醒请导出ICS并在日历应用中设置提醒。个人输入、公共公告和预测彼此独立。

## 标准订阅与开放读取

| 地址 | 格式与边界 |
| --- | --- |
| `/calendar.ics?lang=zh` | 完成公告的发布时间、明确时区的预告窗口；不导出未知时间或统计推算。最多500项，默认100项 |
| `/feed.atom?lang=zh` | Atom公开事件，默认50项，最多100项；原始来源作为纯文本转义 |
| `/feed.rss?lang=zh` | RSS 2.0，口径同Atom |
| `/api/events` | 公开事件JSON，支持`kind/phase/account`、游标分页和独立计数 |
| `/api/monitor` | 公开数据新鲜度、来源与渠道配置摘要，不含凭证和私有错误日志 |
| `/api/forecast-history` | 上线后追加的快照与后验评估，不回填虚构历史 |
| `/mcp` | MCP 2025-11-25兼容的只读无会话JSON HTTP端点 |

ICS/Atom/RSS使用标准文档响应，位于`/api`之外；业务API仍使用`{code,data,message}`包体。导出链接支持`kind=quota/card/other`。ICS使用稳定UID、UTC、CRLF和UTF-8字节折行；它不承诺实际个人到账。

MCP支持`initialize`、`ping`、`tools/list`与`tools/call`，工具仅有`get_monitor_status`、`get_reset_events`、`get_reset_forecast`。请求使用`Content-Type: application/json`，接受JSON响应；每个JSON-RPC消息单独POST。没有写操作、管理员日志、订阅投递操作、个人额度读取或模型调用。GET返回405，不提供SSE会话。服务只实现明确声明的兼容版本，不声称覆盖后续协议版本。

## 预测账本与人工复核

- 每轮检查后追加首次观察到的预测快照，记录窗口、有效模型名/方法、策略版本和证据；相同指纹不覆盖原记录。
- 只评估记录时仍未开始的未来窗口；窗口结束后至少等待一天并确认后续抓取成功。完成公告时间落入窗口才记为窗口内观察到公告；不等于个人额度到账准确率。
- 至少5个有效窗口后显示比例；无可靠预测、已开始的窗口及多账号等记录不进入分母。当前上线前没有可回溯的可信预测账本，不补造过往成绩。
- 管理员可更正分类/阶段、合并同账号同类型事件、用原合并来源ID解除合并、撤回和恢复来源。每项操作需要原因，并记录操作者、时间、原始视图与修订号；过期修订返回409。
- 人工判断影响派生事件、预测采样和待投递资格；原帖、原始AI结论和已发送记录保留。不会把已经送达的外部消息抹去，也不会因复核自动重发。

## 可选访客邮件与Web Push

此功能默认关闭，与飞书/钉钉/企微/Bark/Telegram自用渠道独立。现有`.env`未配置访客SMTP与VAPID时，界面明确显示未配置，不能创建订阅，不请求系统通知权限。

运营者自行决定是否启用，并在自己管理的运行环境配置：

| 配置 | 用途 |
| --- | --- |
| `MONITOR_PUBLIC_SUBSCRIPTIONS` | 显式启用访客订阅，默认false |
| `MONITOR_PUBLIC_BASE_URL` | 实际公开HTTPS源地址，不含路径、用户信息或查询；仅本地调试允许localhost HTTP |
| `MONITOR_SUBSCRIPTION_SECRET` | 独立稳定的随机签名密钥，至少32字符；轮换会使旧管理链接失效 |
| `MONITOR_SMTP_HOST/PORT/FROM` | 邮件服务与发件人；默认端口587 |
| `MONITOR_SMTP_USER/PASSWORD` | 需要时配置的SMTP认证，仅环境读取 |
| `MONITOR_SMTP_STARTTLS` | 默认true；远程SMTP必须加密 |
| `MONITOR_SMTP_SSL` | 使用隐式TLS时设true并配置相应端口（通常465），不再额外STARTTLS |
| `MONITOR_VAPID_PUBLIC_KEY/PRIVATE_KEY/SUBJECT` | Web Push VAPID密钥与联系标识，由运营者生成并保管 |

Web Push使用可选依赖组`webpush`（`pywebpush`）。运营者需要在其自行管理的环境安装本项目的`webpush` extra；助手没有修改用户`.venv`。pip/Docker默认依赖不自动包含此可选能力，未安装时界面显示未配置。

- 邮件订阅先发送24小时有效的一次性确认链接，同一邮箱请求限每小时一次；确认之前不发送事件通知。既有邮箱状态不通过响应差异公开。
- 订阅管理使用独立HMAC能力链接，不授予管理员权限。链接令牌通过URL片段传入，进入页面后清除；API只用POST包体，不放查询字符串或访问日志。退订会撤销旧管理令牌。
- 可选额度/发卡、完成/预告及语言偏好。只发送生效后新事件，重新订阅不补发停用期间历史。投递前再次检查退订、偏好和人工撤回。
- 独立SQLite队列按订阅与事件阶段去重。已被渠道接受的不重发；失败最多5次退避重试，24小时外停止。浏览器410/404自动停用；进程中断会在租约到期后重新领取。渠道接收成功不代表已读，网络应答丢失仍可能造成一次重复。
- 只有明确点按启用后才请求通知权限；Web Push需要HTTPS、Service Worker、Push API和Notifications API。iOS/iPadOS主屏幕Web App需支持此能力；不以桌面模拟测试替代真机验收。
- Service Worker仅处理推送，不缓存API、账号凭证或个人记录。推送点击只打开同源地址。
- 浏览器推送端点仅允许已知浏览器推送服务HTTPS主机，拒绝任意网站、内网、用户信息及非标准端口，防止将订阅接口变成任意地址请求器。
- 邮箱、浏览器推送端点和投递队列属于本地数据库业务数据，沿用`.env/data/`不入库规则。部署应备份数据库并限制文件访问。

## 验收与运行边界

开发实例读取真实`.env`及现有SQLite，设置`MONITOR_CLEANUP_ON_STARTUP=false`；结构变更前保留在线备份。没有为验收改写真实公告分类或创建虚构访客订阅。单元测试沿用隔离夹具；Web Push额外依赖只安装在隔离工具运行环境。

本轮真实飞书专用测试webhook已经验收渠道接收；SMTP、邮件确认到达、浏览器推送服务接收与iOS/Android系统通知尚未实发验收，不能用Mock、加解密回归或桌面窄屏截图代替。未改写`.env`、用户自管环境或用户运行服务。
